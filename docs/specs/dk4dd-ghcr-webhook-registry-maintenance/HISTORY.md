# Dockrev：GHCR Webhook 注册维护专页 演进记录（#dk4dd）

## Decisions

- 仓库维护页采用服务端筛选分页，而不是前端聚合后虚拟化。分页将数据传输、React 对象数和 DOM 行数同时限定在当前页范围内，也保持行级操作的现有语义。
- `q` 保留并扩展到仓库名、状态、Webhook ID 与错误文本，避免状态筛选引入搜索能力倒退。
- 活跃 GHCR 任务按 `queued` 和 `running` 两种状态分别有界读取，不加载完成历史；概览继续是汇总数据的权威来源。
- 页码修复由页面接收服务端 `filteredTotal` 后执行，因此删除仍遵循 worker 最终一致性，而不会前端乐观删除。
- 服务日志虚拟列表的 `data-index` 属于测量接口合同，不应依赖 DOM 顺序推断索引。
- GHCR 行级操作提示以最近的滚动容器为边界计算可用空间；窄视口或已滚动的维护页不会因提示气泡超出内容区而引入横向滚动。
