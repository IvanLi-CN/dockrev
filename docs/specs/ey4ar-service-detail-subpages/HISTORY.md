# Dockrev：服务详情页七子页信息架构升级 演进历史（#ey4ar）

> 这里记录会影响 Agent 理解“为什么一步步变成现在这样”的关键演进；单次任务流水账不放这里，规范正文仍以 `./SPEC.md` 为准。

## Decision Trace

- 2026-06-27: 新建本 spec，冻结 `概览 / 监控 / 设置` 三子页方案、旧链接默认落概览、页头 tabs 导航，以及“高频动作保留 / 低频危险动作下沉”的信息架构重排。
- 2026-06-29: 扩展为 `概览 / 监控 / 备份 / 设置` 四子页方案，把服务级备份摘要、备份设置入口与当前服务相关备份记录从 `设置` 页迁到独立 `备份` 子页。
- 2026-06-29: 将服务详情 IA 增量升级为 `概览 / 监控 / 日志 / 设置` 四子页，新增 Dozzle 风格的服务级实时日志子页，并补充 snapshot + SSE + ring buffer + 搜索/吸底交互契约。
- 2026-06-29: 纠正日志需求漂移，删除“多容器聚合日志”的产品语义，统一回到“单服务日志流”的接口、界面与视觉规范。
- 2026-06-30: 主干新增 `备份` 子页与本分支新增 `日志` 子页完成合流，服务详情最终收敛为 `概览 / 监控 / 备份 / 日志 / 设置` 五子页 IA。
- 2026-07-01: 按 Dozzle grouped log 参考修正服务日志多行语义，将应用多行错误 continuation 保留在同一逻辑日志组内，并避免在等级列重复渲染正文 tracing 级别。
- 2026-07-04: 修正服务日志采集只读取 stdout 的缺口；Docker 容器常把应用日志写入 stderr，snapshot 与 SSE live tail 均需消费 stdout/stderr 双流。
- 2026-07-07: 修正服务日志结构化解析边界；Rust `tracing` 默认文本输出并非 JSON/logfmt，但仍包含应用级时间、等级与 `key=value` 字段，后端需在 text meta 中提取这些字段，而不能只靠前端启发式推断。
- 2026-07-12: 新增 route-backed `更新记录` 子页，完整历史从概览最近三条摘要中分离；基于既有 jobs 读模型统一展示当前服务关联的 update/rollback 任务，并只在该 section 在线时订阅全局 jobs SSE。
- 2026-07-12: 更新记录表将已回滚状态从成功态分离为回滚态，并只在当前服务可回滚目标的来源成功更新任务上提供受控回滚入口，避免将历史列表误解为任意版本回滚器。
- 2026-07-12: 更新记录的记录列收敛为严格两行，避免结果摘要将紧凑操作表拉成三行；长摘要保持可通过 title 查看的单行截断。
- 2026-07-12: 更新记录不再重复显示已由操作类型或状态表达的泛化结果摘要，只保留可补充诊断的结果信息。
- 2026-07-12: 失败任务的弱化范围收窄到非状态列，避免降低失败 Badge 的状态可见性。
- 2026-07-12: 移除更新记录表格的嵌套圆角容器，保留单一 section card 与表头、行分隔线的信息层级。
- 2026-07-12: 移除更新记录内容区中与活动 Tab 重复的标题、说明与数量，仅保留任务表格。
- 2026-07-12: 更新记录超过 20 条时改为客户端分页，只挂载当前页行，并以可访问的上一页/下一页箭头控制浏览。
- 2026-07-12: 更新记录中可解析目标 tag 的操作复用既有右侧 release drawer，定位并高亮对应版本；缺少可靠 tag 时不显示入口。
- 2026-07-12: 收紧 stack-scope 历史关联规则，只有 summary targets 明确命中当前服务的任务才进入列表；同时补齐服务树对 `history` section 的“更新记录”标签，避免深链导航退化为概览文案。
- 2026-07-15: 固定更新记录桌面六列表格的共享列轨道，避免只有部分行出现更新日志或回滚按钮时把 `操作` 列撑宽、连带挤压其它列，导致表头与记录错位。
- 2026-07-16: 版本子页按批注收敛为仓库级图标入口 + 桌面双虚拟列表；左目录固定 `220px`，`≤1100px` 完全隐藏，当前版本与正文中心联动，动作栏固定为 `19rem`。
- 2026-07-16: 共享状态摘要删除 digest、raw tag、架构、规则与原因技术细节，只保留状态、当前版本、目标版本与版本跨度，以便七个子页统一复用。
- 2026-07-16: 版本子页的当前 rollback target 与服务级回滚确认新增“来源备份”摘要；仅在来源更新任务实际纳入备份时显示 included targets 数量与源目标总体积，避免把历史备份语义和可执行回滚语义割裂开。
- 2026-07-17: 修复 Dockrev `版本` 子页 release card 误用普通 service update 的回归；顶部 `升级 Dockrev` 与 candidate 卡现在共用 supervisor 自我升级动作真相源，非 candidate 的更高版本保留禁用解释，supervisor offline 时重试只留在顶部。
- 2026-07-17: 服务详情页 tabs 上方收敛为唯一一条共享状态信息带，移除旧的右侧状态卡与 `Image Ref / Service ID / Stack ID` header cards；这些技术标识改为仅在 `概览` 子页内的“服务标识”卡展示。
- 2026-07-17: 删除服务详情内容区里独立的“服务详情”标题与说明文案；页面首屏只保留共享状态信息带和 tabs，避免重复占用垂直空间。
- 2026-07-17: 在共享状态信息带上方补回一条紧凑的服务监控摘要行，展示服务名与 `CPU / MEM / RX / TX`；监控关闭、离线缓存和暂无样本都继续在同一行表达。
- 2026-07-17: 继续收紧双层页头，删除监控行里的“服务监控摘要”副标题，并从绿色状态信息带中移除重复的服务名与 Stack pill，只保留镜像简述与版本状态信息。

- 2026-07-17: 按 owner 反馈将共享监控行里的文字 label 收敛为图标前缀；可见内容只保留图标与数值，指标语义转入 `aria-label` / `title`。
- 2026-07-17: 删除共享监控行里的独立时间 chip；tabs 上方第一行只保留服务名与六项监控指标，不再混入额外状态 pill。
- 2026-07-17: 为宽度不足的服务详情页头补齐稳定的 `2 x 3` 监控网格；移动端按 `CPU / 内存`、`磁盘读 / 磁盘写`、`下载 / 上传` 三列成对展示，不再依赖随机换行。
- 2026-07-19: 收紧服务详情页版本子页的 rollback refresh 提示触发条件；后台轮询只在当前 rollback snapshot 缺失或与服务当前 digest 失配时才暴露“回滚目标刷新中”，避免 `versionInference=pending` 的常规轮询把顶部提示反复闪烁成告警。

## Key Reasons / Replacements

- 服务详情页已经承载多个主题能力，需要一个新的 topic spec 统一约束子页路由与内容归位。
- 既有自动更新、回滚、Compose tag、资源监控等 feature specs 继续拥有各自能力契约；本 spec 只负责服务详情页的信息架构与导航层组织。
- 实时日志属于高频、长列表、强滚动上下文的独立任务面，不适合继续依附在 `monitoring` 卡片区内。
