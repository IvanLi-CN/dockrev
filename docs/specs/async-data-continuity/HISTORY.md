# Dockrev 异步数据连续性与加载反馈 演进历史

> 记录影响长期行为的决策原因；规范正文仍以 `./SPEC.md` 为准。

## Decision Trace

- 使用区域级状态而不是整页全局 loading，避免多请求页面因一个失败域而失去已成功内容。
- 冷启动不设置最短骨架时长；已有内容只在真实慢请求时以 200ms/800ms 门槛显示遮罩，避免短请求闪烁。
- fresh snapshot 保持既有 60 秒边界，并通过 v2 readiness 和 committed query key 消除旧 payload 的“空即成功”歧义。
- 时间窗以当前时间而非最后一个样本为锚点，防止长时间离线缓存把历史样本伪装成当前监控数据。
- mock-only 视觉确认覆盖冷启动、缓存刷新、错误恢复三态，并固定桌面与移动端证据，作为后续 PR 收口基线。
- review 收口继续坚持域级隔离：服务核心失败保留已提交内容并原地重试，快照写入采用完整 readiness 门槛，交互测试通过显式刷新复现可恢复路径。
- 服务详情复审进一步收敛局部失败与用户刷新语义：核心、设置、回滚、备份分别报错，缓存备份不因 live 失败消失，写操作等待备份域 ready。
- 最终交互复核补上二次刷新 live 数据优先级，并统一 Stack 刷新和 GHCR 页数选择器的请求中禁用反馈。
- Job Detail 首屏读取与管理事件首次重同步曾以两个并发请求竞争，后到的 silent 结果会让先到结果失效；当前合同改为按任务合并自动序列、为快照设置 10 秒截止并提供一次自动恢复，用户刷新可取消并替代该序列。
- Job Detail 无数据错误态以透明的亮/暗双色插图替代简单错误图标；为避免自制或不可追溯视觉资产，使用 Adobe Spectrum `@spectrum-icons/illustrations` `Error` 的 Apache-2.0 SVG 原稿。两主题复用同一份可见几何并只通过 Dockrev token 调整颜色，视觉审查方式见 [VISUAL_REVIEW.md](./VISUAL_REVIEW.md)。
- 首屏无数据失败不再把错误提示叠在骨架上；错误态独立占据稳定的数据区域高度，并以居中的详情不可读取插图、文案和重试入口表达恢复路径。
- 视觉复核发现服务器线条的右侧面积会改变感知中心；Job Detail 错误态在不改变插图几何、文案或按钮主轴的前提下，桌面向左 `6px`、移动向左 `5px` 做光学校正，并将插图与恢复组的间距固定为 `32px/28px`。
