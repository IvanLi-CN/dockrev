# Cleanup interactions read the existing snapshot

Status: accepted

Dockrev 的清理页与清理动作弹窗读取服务端已有的清理快照，而不是在每次页面打开或按钮点击时强制全量扫描。处于 300 秒新鲜度窗口内的快照会立即打开弹窗，并可直接作为执行依据；服务端的新鲜度、fingerprint 与 volume 实例校验仍是唯一执行闸门。为避免用户在窗口末尾点击时等待，前台清理页会在快照临近过期时主动刷新：提前量按最近一次扫描耗时自适应（60–240 秒），连续 30 分钟无交互后停止。确认弹窗打开期间暂停主动刷新；显示数据一旦过期，弹窗切换到发现态并禁止用旧数据确认。

## Considered Options

- 点击时强制重扫（原实现）：每次点击都要付出逐资源 `docker inspect` 的全量扫描成本，并没有增加服务端已有校验之外的安全性。
- 命中快照后仍后台重扫，同时保持 apply 等待扫描：扫描运行期间 apply 被拒，等待只是从点击时转移到确认时。
- 过期快照加警告后仍允许确认：把“用户看见了什么”和“服务端会执行什么”重新混在一起，废弃。

## Consequences

- 前台清理页大约每个新鲜度窗口触发一次扫描；扫描成本仍然存在，只是从用户点击路径移到了前台空闲路径。
- apply 与扫描可以重叠；原有“扫描全程互斥”的门闩改为独立的删除互斥门闩与扫描单飞，Stack 记录删除仍与快照最终写入、apply 互斥。
- `partial cleanup snapshot` 只能展示，不能进入确认或 apply。
- 自动刷新失败按指数退避，不阻塞仍新鲜快照的执行能力。
